## 兩份的共識

- **擋不住的限制**：寫入範圍、不能 commit、只有 qa 能試玩，這些規定都只靠 .md 文字和 agent 自律。shell、run_python、self_tools、tools_def 都可以繞過；只拿掉某個工具名稱也沒用。
- **給下屬的限制要是硬的**：唯讀的原始碼快照、獨立的可寫產物區、不能碰 .git 和別人的 stack、網路要切斷、資源要有配額，而且子程序不能自己解除這些限制。現有的 `ws` 只是預設工作目錄，不是牢籠。
- **flock 是約好遵守的鎖，不是強制的**：它只能讓工作排隊一個一個跑，限制不了程序數。使用者已經確認要限的是工作數，目的是不讓 CPU 和記憶體被吃光。
- **常用程序做成受控工具**：dev 要的是逐塊 test 加 build 的驗證器，qa 要的是 E2E runner，包含預檢、快照、鎖、埠和 JSON 結果。
- **信寫短一點**：細節另外存檔，信裡只附路徑。開工信要固定寫出範圍、基準、驗收分工、資源規矩，以及預期會有哪些並行變動。
