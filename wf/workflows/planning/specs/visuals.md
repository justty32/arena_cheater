# 詐賭競技場 — 視角、骨架與紙娃娃

[玩法規格](cheating-arena.md)｜[開發計畫](../plans/cheating-arena.md)

## 來源

2026-11-11 使用者在本輪規劃中追加，原文如下：

> 以45度俯視角。2d。素材先用canvas畫

> 骨骼動畫、紙娃娃

這些是本次方向要求，需進入第一個可玩切片。以下投影公式、骨架欄位與分層方式是實作提案；使用者沒有指定外部引擎、骨架編輯器或相機方位角。

## 方案 / 取捨

採 2D Canvas 畫面與程序繪製的角色部件、裝備、場地素材，先以簡單獸人輪廓驗證可讀性。部件生成結果可快取成離屏 Canvas，再由骨架變換組裝；用幾何圖形產生素材，不需要圖片生成服務或外部美術。卡牌與資源面板可沿用 DOM，使鍵盤、點選與文字仍易操作。

紙娃娃定義為身體部件、外觀與裝備分件裝配；骨骼動畫定義為有父子關係的骨頭及姿態插值，不只把整張角色圖旋轉或縮放。最小骨架建議含根／骨盆、軀幹、頭、左右上下臂與手、左右腿和腳；頭部變體與耳角尾等依鬥士特徵掛接。裝備插槽掛在手部骨頭，層級保存局部平移、旋轉、縮放與樞紐點，從父骨變換算出部件位置。

建議先用自有小型骨架資料及渲染器，直接支援本輪姿態與插槽，避免為暫用素材先導入工具鏈。若往後大量製作動畫或需要成熟編輯器，再比較外部骨架工具；部件 id、樞紐、骨架、裝備插槽與動作名稱不得綁死 Canvas 繪圖函式，才能用正式圖片替換而保留資料與行為。

## 世界座標與投影

模擬仍在直徑 15 m 的圓形平面運作，與相機分離。45° 指向下看場地的俯視傾角；不擅自把場地繞垂直軸也轉 45°。建議正交投影、畫面上方為場地後側，世界地面 `(x, y)` 投影為 `(originX + scale*x, originY + scale*y*sin(45°))`；空中高度 `z` 的畫面位移另減 `scale*z*cos(45°)`。因此圓場在畫面上成橢圓，不能拿橢圓螢幕距離算遊戲射程。

地面投放由游標經反投影得到公尺座標，縮放、Canvas CSS 尺寸與 device pixel ratio 均須計入；場界、陷阱、拾取及碰撞在世界空間驗證。點鬥士則按投影後可見選取輪廓判定，重疊時建議選最前方可見者並先顯示高亮；不得只依腳底點的小圓讓角色身體點不到，也不得點到被完全遮住者。選取規則不改模擬的受擊碰撞體積。

## 動畫、裝備與遮擋

P1 即提供待機、走路、徒手攻擊、受擊與倒地姿態；P2 加控制倒地／起身，P3 加持單手、雙手與盾的姿態。骨架姿態由模擬的動作、進度與事件時間決定，準備／命中／收招可用不同姿態段；動畫播放不另觸發傷害。暫停時姿態播放與飛行停止；暫停出牌可立即更新靜態狀態或建立投送物，但動畫進度、狀態倒數與飛行要繼續後才推進，調速後與同一遊戲時鐘同步。

單手裝備占一手，雙手裝備占雙手並用另一手配合支撐，不能生成第二份武器；拾取、耗盡與斷裂事件改變對應插槽外觀。盾牌朝向、格擋姿態與正面防禦必須一致，紙娃娃的純美術換色不能改能力，裝備能力由核心狀態決定。

角色之間按腳底地面深度排序，前後肢、武器與盾依朝向切換局部層次；不能只畫固定左右手而讓盾永遠蓋住臉。擊飛提高畫面位置但不把高度當地面深度，地面陰影仍顯示落點。巨大／縮小以腳底為錨同步外觀尺寸與模擬半徑，攻擊閃光／傷害數字可獨立一層，避免文字被場景遮住。

## 驗證

投影與反投影對任意合法地面點往返得到同一位置；在視窗縮放及高像素密度下，點出的落點與預覽一致。七人前後交錯時，前方角色正確遮住後方角色，選取高亮與最後施法對象一致；盾與武器隨轉向變換，不出現手與裝備分離。

換直劍／圓盾／雙手木棍能觀察正確插槽及姿態，攻擊、受擊、跌倒、死亡有不同姿勢；暫停且未出牌時姿態不變；暫停施法造成的姿態改變停在新狀態，不自行播放。相同遊戲時間在 0.25× 與 3× 得到相同姿態進度。擊飛保留地面影子，尺寸變化不讓腳底漂移。降低動態效果可省略震動、誇張位移與裝飾特效，但保留動作姿態、方向與命中資訊。

以自動化測試驗證座標轉換、插槽占用及時間同步，瀏覽器驗證點選流程；骨架自然度、遮擋和鬥士辨識需記錄人工畫面驗收。Canvas 像素本身不代表語意，角色選取、生命／體力與出牌結果應有對應 DOM 文字或可存取控制，延續可操作性。
