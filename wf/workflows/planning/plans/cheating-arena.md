# 詐賭競技場 — 分期開發計畫

[規劃入口](../README.md)｜[玩法規格](../specs/cheating-arena.md)

## 目標與狀態

七人圓場、45° Canvas 骨架紙娃娃與基本卡牌快版已落地並獲試玩接受，暫停出牌已修。**P3 裝備戰與防禦已落地，P2 虛弱體力已補齊**；P4 完整內容、P5 平衡仍未完成，分期不承諾日期。

來源與補足規則見 spec，[需求清單](../data/cheating-arena-requirements.json) 的 P1～P5 表示分期、D 表示延期。開發依 [feature-dev](../../feature-dev/README.md)，修改前核對 [code map](../../common/code-map.md) 與目前分支。

## 方案落點與共用契約

沿用既有狀態、seed、時間與生命週期設計；格位、職業戰鬥與鎖定追蹤投射物須重做。新模擬按狀態／幾何／戰鬥／介入拆職責，由 code map 登記實際路徑。

模擬狀態包含公尺座標、面向與半徑、鬥士資源及效果、巫師資源、飛行裝備、落地裝備與陷阱；輸入是帶 tick 的「選卡作用於鬥士／座標」指令，輸出是狀態快照與事件。只有模擬層決定有效性、扣費、傷害、碰撞與拾取；UI 不能依動畫結束事件扣血。相同 seed 與指令時序應得到相同結果，暫停停止所有遊戲計時但仍接受出牌：法術狀態與投送物立即建立、有效費用扣一次，倒數及飛行恢復後才推進。

核心與瀏覽器測試保留新舊模式回歸；首頁採新競技場，舊原型另有入口，路徑見 code map。視角、骨架、紙娃娃、Canvas 素材及命中規則依 [演出規格](../specs/visuals.md)。

## 步驟

### 已落地切片與剩餘範圍

快版的支持者、七人混戰、法術／投裝備、骨架紙娃娃與結算已獲試玩接受，P1 基礎及 P2 點選／拖曳與暫停出牌已落地。

已補弓三箭、木棍耐久與擊飛／跌倒／起身、雙手槽、盾招架／格擋、投送掃掠、虛弱體力。暫停仍可出牌且不推進時間；僅等待末箭結算時禁止再出牌。

之後仍有 P4 的另 11 種武器／盾、五法術、三陷阱及狀態互動，三種鬥士特性和 P5 投注細節／敵對巫師／平衡。野獸與地形明確延期。

### P1 — 圓場與七人徒手戰

先建立 15 m 圓場、八門、七名鬥士與可控 seed 入場，加入連續移動、角色分離、場界限制、面向和選敵。攻擊分準備／命中／收招，消耗體力，停止攻擊 2 秒後慢回，長休快回；生命歸零停止行動。以七種外觀／名稱進場，只有狼、熊、象、牛使用原文明確特性，其餘不補發新能力。此階段可不包含裝備，象的鈍器加成契約先預留至 P3。

完成條件：seed 重播一致，角色不越界、卡死或攻擊死者；體力不足不能攻擊且休息能恢復，2 秒與快回門檻有測試。瀏覽器可開始、暫停、調速、重置並看見面向、出招、血量與體力；七人可結算。Canvas 以 45° 呈現圓場，角色有父子骨架與分件外觀，走路／攻擊／受擊／倒地可辨識；投影／反投影與遮擋選取可驗證。只交付骨架程式不算完成，須能觀看一場戰鬥。

### P2 — 一名巫師的法術介入

加入玩家法力、自動恢復、固定卡列、選支持者與對局結果。先做興奮、怪力、虛弱及未命名跌倒法術，打通「選卡／拖卡→合法目標預覽→提交→扣法力→狀態與演出→到期解除」。支持對方鬥士作負面法術目標，不沿用舊藥劑只能選己方的限制。

完成條件：兩種輸入得到同一核心指令效果；法術點地、死者、場外、資源不足、取消、未開戰、結算後及等待末箭結算時施放都不扣法力；交戰與暫停中的有效施法／投送均只扣一次。暫停出牌後世界時間、資源恢復、效果倒數及投送飛行保持凍結，恢復後才推進；效果到期還原，重複施放遵守規格。手機可用點選操作，畫面能辨識支持者與剩餘資源，縮小畫面不遮住主要瞄準區。此階段用定值法力參數，先取得一次完整介入試玩，再調平衡。

### P3 — 投裝備、拾取與方向防禦

加入金錢及選定補充規則、玩家投擲物、碰撞落地、拾取與手部槽。先做直劍、圓盾、木棍、弓，驗證近戰、盾、擊飛／耐久與有限彈藥四種路徑。武器有飛行時間、落點不追蹤角色；碰撞掃掠與同 tick 拾取必須可重現。加入正／側／背傷害判定，背擊倍率與格擋／招架契約於此階段開始前定下。

完成條件：投擲只扣一次金錢，相撞物正確落地，遠距拾取不成立，搶一件只一位持有者，單雙手槽合法且紙娃娃掛手／支撐姿態一致；側面不防禦，背擊依倍率，圓盾具兩種防禦結果。木棍及弓可耗盡後繼續戰鬥；象鈍器加成有測試。用交錯飛行裝備檢查高速穿透與倍速等價。

### P4 — 狀態、武器及陷阱內容補齊

完成清單其餘利器、鈍器、盾、屎，並加入瘋狂、疾病、酒精、巨大與縮小。先完成控制狀態優先序、尺寸改變、擊飛後跌倒、破盾／繞盾，再填卡牌資料；最後加入捕獸夾、刺洞、絆倒繩。野獸與地形始終排除。豪豬豬、蛇、鹿若仍未有特性決策，維持基準能力並清楚標示，不讓開發自行定案。

完成條件：需求清單 P4 每筆都有行為測試或明確人工驗收紀錄；死亡不能被狀態刷新復活，巨大縮小替換不累乘，瘋狂不免疫未指定控制，酒精可重現，疾病延遲後只按規則觸發。流星錘繞盾、斧破盾、巨大鈍器無視防禦擊飛、縮小擊飛兩倍、屎無視防禦並持續傷害及虛弱 5 秒均有交互案例。陷阱所有陣營可踩，移除後不再觸發。

### P5 — 對局閉環、可讀性與平衡驗收

依已選方案補齊投注／結果呈現、金錢節奏及其他巫師（僅在確認要做時）；未確認的賠率與持久經濟仍不實作。用固定 seed 場景與實際試玩調整干預頻率、控制連鎖、戰局長度與閘門視認；保留慢速、暫停、降低動態效果及窄螢幕操作。將現行規則、操作與可調值寫入產品文件，更新 code map 與測試導航。

完成條件：三場固定 seed 正常結束，支持者勝敗、全滅／超時及在途傷害結算有案例。人工驗收填寫攻受擊、方向、介入可讀性及金錢節奏的通過／待調結果；工程通過與趣味性分開。

## 多 agent 分工與依賴

整合者先定共用型別、事件與驗收，再拆模擬、UI、內容及測試工作；同檔只由一人寫。幾何穩定後才做拾取／投擲，指令契約成立後 UI 與核心可並行；裝備／狀態介面固定後再拆內容批次。測試依需求寫反例，不複製實作預期。

整合者逐階段核對 spec 與來源，將新決定登記到 [decisions](../../decisions.md)，改動跨模組時更新 [code map](../../common/code-map.md)。本計畫不授權 agents 擅自擴充野獸、地形、經濟或外部服務。

## 驗證

規劃文件核對來源逐字保留（忽略 CRLF／LF）、清單覆蓋、相對連結、錨點及導航。遊戲實作另依下述驗證，不以規劃驗收代替；完整工作流 lint 僅在使用者要求時執行。

後續每階段修改遊戲邏輯後執行 `npm test`，TypeScript／UI 修改執行 `npm run build`，互動或戰鬥整合執行 `npm run test:e2e`。使用 [testing](../../testing.md) 的環境與分層，不把只有建置成功當作互動驗收；新增測試應覆蓋上述轉換與失敗情境。若某檢查無法執行，記具體原因與接手方式，不標通過。

## 交接

快版完成後對照 P1～P5 記錄剩餘範圍。進度只在 [SESSION-LOG](../../../SESSION-LOG.md) 留 open，真正需使用者裁示且阻擋當前階段才放 [WAIT_USER](../../../WAIT_USER.md)。全部開發完成後才將 spec／plan 依規則封存；快版完成不等於完整計畫完成。
