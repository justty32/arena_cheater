# 提交與發布檢查表

[角色卡](../README.md)｜[改進紀錄](../improvements.md)

## 提交前

- 讀原信、角色卡與公告；main 明列路徑是唯一清單，不用 `git add .`。
- 核對驗收：遊戲需 review／qa，aos 工具需 review／實跑，文件依免審標示。
- 定義檔不能只按副檔名分類；若 main 明列文件批次且已確認定義檢查通過，可依低風險例外判斷收錄，回信交代依據；涉及工具權限或執行行為的不確定變更仍先問。
- 查 status 與 cached 清單；他人暫存先釐清，不自行移除。
- 讀指定差異，新檔逐一確認，不強制加入忽略產物。

## 暫存與提交

- 僅 add 指定檔，再核對 cached 清單、stat 與腳本執行位元。
- 跑 cached 空白檢查；只豁免 design-sources 使用者原文。
- 訊息依 main 要求附驗證及署名，不把他人實跑寫成自己已跑。
- 每批獨立提交，不 amend；下一批重新核對並行修改。

## 提交後

- 查 log 與 status；剩餘檔歸入已知批次，不強行清空。
- DONE 回原信，附 hash、剩餘變更、例外理由與未完成事項。
- 無使用者原文授權不 push；有授權才核對遠端與分支、追蹤 CI／Pages。
