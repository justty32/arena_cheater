# V3 第一切片：戰鬥數值尺度

[資產庫](../README.md)｜[執行計畫](../plans/v3-first-slice.md)｜[候選差異表](../data/v3-first-slice-proposal.json)

## 授權與範圍

本規格是 2026-11-25 提案，不是落地完成宣告。來源為 [V3 原文](../../../../../docs/design-sources/cheating-arena-v3-2026-11-23.txt)；[四題裁示](../../../../workflows/decisions.md)暫採整套戰鬥尺度、持用加值、背擊維持與完整失控三秒、豪豬蛇標準模板。真人遊戲策劃仍可改。main 補充牛體力依原文保留物種差異，不以標準體力封頂。

本批涵蓋七種鬥士基本能力、既有持用武器、狼象特性、耗體與恢復、防禦及控制時間。碰撞半徑、場地、進場位置與美術不變；一公尺直徑另開 art 切片。惠惠、種子、未實作內容及恐懼 N 等留白不填 runtime。投送、法術、資源循環、裝備耐久及彈藥不調數值。豪豬、蛇不新增特性。

## 數值與資料契約

候選差異表是唯一的新值提案，收尾建議版含 74 列 update / keep / add / remove（原 73 列加 world.matchDuration）、現值、A/B、單位及依據；不是第二份 runtime 設定。未列欄位全部維持基準 `46935cfd685baad74c278c8888d109fa8c6ce45d`。現行權威仍是 `src/arena/data/arena-balance.json`，本次規劃不改它。

原文鬥士與武器數值依原文；持用傷害作加值及豪豬蛇模板是使用者暫定。武器、象、fury 倍率必須換成新 hp 加值 id，不可把舊 multiplier 的單位直接改掉。新增 club 耗體，停止 fallback 一般攻擊。id、schema、loader、雙表增刪皆由 dev 寫；差異表的新名稱待 dev 確認。依 main 2026-11-25 指派，本批兩張 runtime 表（含既有列）由 dev 單一寫手處理；design 不寫表，待 dev 完成後依 proposal 與 spec 核值。

本批實際修改／新增列的 metadata decision 使用「暫定（2026-11-25 使用者照 main 推薦；待遊戲策劃確認）」。source_path 指原文或本規格；source_locator、rationale 分清原文、暫定解讀與設計預設。keep 列僅表達依賴，不要求無故改寫其歷史依據。

## 傷害公式與精度

持用基礎傷害為 `(拳傷 + 持用武器加值 + 象木棍加值 + fury加值) × 虛弱倍率 + 嗜血加值`。拳與盾沒有武器加值；象只對現有鈍器 club 生效；狼擊殺刷新 fury，不累加層數。投送不使用此公式。

狼象先加後乘是四題裁示；嗜血仍在虛弱後加，保留現碼語意。本輪早期口頭沙盤方案曾把嗜血移到虛弱前，現已撤回並通知 dev，不納入本提案。全免招架先處理，否則沿用背擊判定及盾牌格擋倍率。正傷害在所有適用倍率完成後四捨五入至 0.01 hp，最小正傷 0.01；零傷仍零，不再保底一點。每次扣血後同樣正規化至兩位小數，最低為零，避免浮點殘血；這是可調預設，不是原文要求。既有直接法術／持續整數傷害不變。

例：標準拳背擊為 1.2；標準拳正面格擋為 0.5；虛弱拳格擋為 0.28；象木棍未加狀態為 6；熊木棍為 5。狼持劍 fury 加虛弱與嗜血為 `(1+1+3)×0.55+3=5.75`，再進行方向／防禦處理。這些是算式驗收，不是戰局實跑。

## 生命與傷害顯示

可調預設：UI 與 log 的 hp／傷害統一顯示最多兩位小數，去掉小數尾零；例如 `9.72`、`9.7`、`10`、`0.01`、`0`。不無條件進位、不只顯示一位，避免活著的 0.01 顯示成零，或 9.72 假裝是十點。生命分子與上限、傷害數字使用同一格式；格式化不回寫狀態，也不影響死亡判定。既有 log 若沒有 hp／傷害資訊，不為此新增逐擊洗版紀錄；有顯示數字的地方則一致處理。

套用位置包含鬥士名單、詳情、支持者 HUD、既有傷害回饋與戰鬥紀錄；不能只改詳情而留下其他地方 Math.ceil。血條寬度仍依實際 hp/maxHp 比例，進度條 aria-valuenow 使用正規化後的實際 hp，最大值使用 maxHp，不把文字顯示的省略尾零當成不同數值。桌面及手機都需能容納 `100 / 100` 與 `99.99 / 100`，不可省略有意義的小數。時間與體力顯示不因本條一併改格式。

## 射程語意

原文公分換成公尺。近戰距離暫解為兩鬥士碰撞體表間隔，起手檢查 `中心距 <= 雙方半徑和 + startGap`；命中重檢 `中心距 <= 雙方半徑和 + hitGap`。命中容差暫定起手另加 0.2 m，避免 windup 後極小位移必定落空；拳與盾起手沿現況。弓採中心距，射程不另加半徑；箭飛行碰撞仍用現有掃掠及 padding，不能混同起手射程。windup、拳盾攻擊 CD 及弓彈道壽命沿用。所有體表／中心距 metadata 應明示，不以 art 的未實作尺寸推算。

## 防禦與恢復提案

推薦 A 作第一個試玩候選，不宣稱已平衡。標準體力降至十點後，原本防禦與移動門檻會把多數行為封死，因此同步縮放。格擋半點、招架一點，讓全免防禦比半傷防禦昂貴；圓盾原文耗體是 x，這兩值都是可調預設。原文圓盾 CD 半秒暫映射到招架再用間隔，不是盾拳攻擊 CD。招架威脅窗、正面判定、反震不變。

停攻滿兩秒可恢復；停移滿 2.5 秒用快回，否則慢回。A 每秒快回二、慢回一；B 只有這兩項減半，測試較重的耗盡懲罰。A 標準空槽需五秒快回或十秒慢回的有效恢復時間，另加等待門檻；這是解析推算，不是模擬結果。保留成功防禦重設 lastAttack，故長期受壓不保證能恢復。移動門檻改零而不新增移動耗體，空體力可移動但不能免費攻擊。虛弱體力上限倍率、恢復先於控制判定（倒地仍可回體）的既有行為不改。

## 控制時間

完整擊飛至可行動總計三秒是使用者暫定；分段暫定擊飛 0.35、倒地 2.3、起身 0.35 秒。轉段 deadline 必須接續前一段期限，不用當前 tick 重新起算；跨越多個期限時須推進到當前正確狀態，避免每段再多耗一幀。可恢復行動的第一個 tick 應在開始後三秒至三秒加一個 dt 以內。再次受擊、死亡、定身等既有優先序不因此免測；捕獸夾三秒定身是獨立規則。

## 戰局比較與決策限制

首輪已實跑，永久證據見 [dev 沙盤報告](../../../dev/assets/v3-sandbox-2026-11-25/README.md)及其 summary.json／逐局 results。現況 100 局全部決勝，平均 27.916 秒、中位 27.3 秒，七物種勝率（狼／熊／象／牛／豪豬／蛇／鹿）為 8／31／29／19／13／0／0%。A、B 各 100 局全部在 180 秒超時平局；截尾平均與中位均為 180 秒，決勝局戰長無樣本，各物種勝率均零。三組成功介入數皆零。A 末態平均存活 4.35 隻、剩餘 hp 總和 190.804；B 為 4.71 隻、251.38。不能把所有勝率零當成物種弱勢或平衡。

實際 archive 基準 7d9b7bb 與 proposal 基準 46935cf 的 src 無差異，dev 已逐列核對 old_value/unit。三組全員裸拳、無盾無裝備，dt=1/30；時鐘浮點累加可能到 180.033333，統計截尾按 180 秒。首輪命中／傷害／缺體力／防禦次數未收集；dev 另補診斷與變體，不從缺少的欄位推測原因。

首輪結果不支持直接落地 A 或 B，也不能只靠恢復選項宣稱已解決收尾。main 已同意暫停原案落地；長時限、起始武器及比例變體已補測，收尾建議見下一節。推薦 A 原先只有尺度與恢復等待的理由，並無已平衡證據。

首輪比較使用 seed 1..100，三組相同種族席位與 tick、180 秒上限；保留逐局 seed、勝者或平局、遊戲時間及介入數。至少先跑無介入組（成功介入數固定零，不代表真人出牌空間）；若加自動介入組，必須三組共用公開、可重現的支持對象與合法操作政策，獨立報告，不能冒充人類試玩。戰長須列全局截尾平均／中位數及已結束局摘要，勝率分母固定全部局數，平局另列；100 局只供方向比較，不保證統計顯著。

開局只有拳、沒有外加裝備的比較不能驗證武器平衡，必須揭露初始裝備；武器公式、盾防及狼象交互以定向核心測試補足。若三組大多超時，先報風險與再次調整選項，不能偷偷延長比賽或加傷害。依使用者 2026-11-25 後續授權，遊戲機制與數值先由 main 採推薦暫定，不逐項詢問使用者。A/B 等戰局比較後由 main 定，設計建議先以 A 沙盤與試玩，main 未批准前不落 runtime。近戰／弓距離、兩位小數與控制分段由 main 先採為可調預設，保留索引供真人遊戲策劃回看。

## 收尾建議：A300 與時限裁決

建議 main 暫定採候選 A，僅把比賽行動時限延長至 300 秒，配合存活 hp 比例裁決。不改原文生命、拳傷、體力與武器加值，不削熊、不加起始裝備、不改法術／投送絕對傷害。74 列提案的 candidate_a 即給 dev 的建議落地數值；新增判勝語意由 dev 實作，不新增無意義的數字型開關。main 於 2026-11-25 信 01795568094140926660.506618.355884 已暫定採本方案與74列表 candidate_a，交 dev 實作，待真人遊戲策劃確認；不表示實作或驗證已完成。

依 [診斷證據](../../../dev/assets/v3-sandbox-2026-11-25/diagnostics/README.md)，A900 全部自然結束，平均 255.807 秒、P90 283.833 秒、最長 343.767 秒。300 秒高於這批 P90，保留多數裸拳局的自然收尾，且不像 900 秒任由尾端拉長。[補驗](../../../dev/assets/v3-sandbox-2026-11-25/follow-up/README.md)的 A300 為 98 局自然結束、2 局比例裁決、0 真平局；截尾平均 255.103 秒、中位 247.967 秒、P90 283.833 秒。這是固定 seed 樣本的預期參照，不保證其他 seed 或玩家介入後零平局；比例裁決也沒有加快其中 98 局的戰鬥。

B900 平均 307.191 秒、中位 297.533 秒、P90 341.033 秒，同樣全部自然結束；相對 A900 平均多 51.384 秒，勝者分布相同。因此選 A 有長賽數據支持，但不能推論所有政策都必然 A 快。缺體力確實占 A 存活時間約 39%～47%，不能因不是永久卡死就說恢復沒有影響；本輪不另調恢復延遲或拳 CD，以免增加變因。

判勝順序：沿用停止行動及待結算規則，先等在途投送、箭矢與既有持續傷害結算完畢，再讀最終存活者。只剩一人為殲滅勝（報告另標是否已跨時限）；全滅為平局。到達時限且仍有多人，令 H=round(hp×100)、M=round(maxHp×100)，以 H1×M2 與 H2×M1 比較比例，唯一最高者裁決勝；最高比例有多人完全同分則平局，不另比絕對 hp、傷害量、物種順序或隨機。只讀存活 hp>0，禁止先把比例四捨五入成百分比再判。裁決不是傷害，不擊殺敗者、不發擊殺補石、不觸發 fury。dev 需提供自然／時限裁決／平局的結果理由，UI 與 log 明示「時限裁決：剩餘生命比例最高」，不假裝裁決者擊殺了所有敵人。

300 秒是停止新行動的門檻，不是包含延遲傷害清算的絕對牆鐘上限。保留原有清算期禁新出牌規則，不為準點收尾丟棄已成立攻擊。報告需分開記行動時限、實際終場時間與是否經過清算；首輪裸拳無在途物件，A300 分析層裁決尚未驗證正式引擎及有持續傷害的終場整合，dev 必須補測。

比例判勝取代超時全平局，卻可能鼓勵保血、避戰或終場治療；高生命者不因絕對餘血多直接勝，但相同承傷下高上限更容易維持比例，並非消除熊優勢。保留同分平局避免偷偷引入任意破同分規則；若之後平局仍多，由 main 另定調整，不先加縮圈或加速機制。

## 待真人策劃回看與作弊驗證

熊在 A900／B900 皆勝 98/100；起始隨機近戰武器組勝 77/100（98 自然、2 超時）；僅生命除十的偏離原文實驗熊仍勝 97/100。這些是自由混戰、無作弊的固定樣本，顯示延長時間或壓低血量並未消除熊優勢，不能宣稱已證明唯一原因或真人局同樣比例。這批保留原文熊 150 hp／拳 2，由真人策劃回看是否接受熊作為作弊優先目標。生命除十雖平均僅 19.670 秒，但偏離原文且未改善熊優勢，不推薦。

有限直接法術政策已補測，沒有顯示實質縮時，不以「法師是看點」代替證據。針對熊可能抑制最強輸出並延長後段，也可能改變狼存活與狂熱，不能用額外傷害除以總 hp 外推戰長。main 已批准獨立自動介入組：A300、seed 1..100、固定支持狼，t>=5 起每五秒嘗試一次，按手牌順序取第一張可支付且合法的 lightning／lightning-rain／divine-wrath；目標優先活熊，否則 hp 比例最高活敵，同分採初始鬥士順序，範圍法術落目標中心。正常牌庫、支付及補牌，不重抽、不注入資源；無合法牌不動，狼死停止。實測 3664 個窗口僅成功 8 次（8 局各一次），其餘 3656 次未成功；敵方有效 hp 損失共 18、友傷零。自然／裁決／平局仍為 98／2／0，勝者仍熊98、象1、牛1；平均 255.078 秒，較無介入 255.103 秒僅短約 0.025 秒，中位與 P90 相同。永久逐窗口證據見上述 follow-up 報告的直接法術節。

此政策不含裝備、治療、投送或持續傷害，也可能因手牌阻塞而少有操作，不代表真人或最佳策略。報告須另列成功介入數、實際敵方 hp 損失（不含 overkill）、友傷、勝者及三類收尾。不得與無介入組混算平均；該組不阻擋 main 定案；未測其他介入政策與真人操作的限制仍須保留。

待策劃發現：在本有限政策下，作弊很難啟動，可能與「場邊作弊是看點」的定位衝突，值得另檢視手牌循環、資源取得與支付可達性。本次只記錄、不改經濟。3656 個未成功窗口不能全稱為付不起：沒有符合的直接法術時也算未成功，而且此政策刻意不重抽、不用其他牌；未分解失敗原因前不能斷言資源不足是唯一主因，亦不能直接歸因為 V3 新造成的退化。
