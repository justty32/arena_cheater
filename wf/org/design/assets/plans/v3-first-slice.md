## 步驟與交接

1. design 交付 spec、74 列收尾候選差異與預設索引。main 確認第一切片範圍及 A/B 選擇；固定 seed 比較未到時明示未實跑，不阻擋使用者先審文件。
2. dev 擴充受控 arena_verify 隔離 workspace 能力，經 review 後在隔離副本實現候選。現況／A／B 各 100 固定 seed；保留 revision、候選差異、命令、dt、初始化與逐局資料，結果交 design 解讀。工具失敗不繞過；沒有結果就保持未測。
3. main 批准落地後，依 2026-11-25 指派由 dev 作本批兩表唯一寫手，處理既有值、新加值 id、club 耗體及移除倍率 id，同步 schema／loader／metadata。design 本批不寫 runtime 表；dev 完成後由 main 派 design 核對值、單位、來源與暫定標記是否符合 proposal 及 spec，差異回報 dev 處理。
4. dev 實作傷害、兩位小數、控制 deadline 與文案，補核心測試；design 只在收到行為回報後同步產品文件，不先把提案寫成既有功能。review 審公式／表／metadata 一致性；qa 做戰鬥與 UI 回歸。
5. main 收齊 review 與 qa 結果交 integration 提交。截圖因能力與文案變更可能不同，先說明差異才存基準；沒有真人試玩就明列趣味未驗。完成後 design 才封存計畫。

## 工程驗收

數值表驗收要求每個候選 update 都比對值與單位，keep 不產生無意漂移；新增／移除 id 雙表與 schema 一致且唯一。所有半徑、卡費、投送、法術、資源、耐久與彈藥須與基準一致。原始倍率完全無 runtime 引用，不允許只新增加值但仍乘舊倍率。metadata 改動列依規格標暫定，來源定位可讀。

傷害核心測試涵蓋七種拳傷、五武器加值、象 club 限定、狼擊殺刷新與到期、fury 與 weakness 先加後乘、嗜血維持 weakness 後加、投送不套持用公式。核對規格算例，另測背擊與盾防方向、招架零傷、零傷不保底、微小正傷、累扣 hp 歸零與擊殺只發一次；文案不能仍顯示象百分比或舊倍率。

體力測試涵蓋牛上限例外、斧棍獨立耗體、其他武器一般耗體、等於成本可出手與低於成本不可出手；空槽可移動、不能攻擊。檢查停攻／停移門檻前後、快慢回切換、成功防禦延後恢復、招架再用間隔、虛弱上限及倒地回體。全免與半傷防禦須各驗成本及不足時的退化行為。

距離測試以不同半徑的雙方核對近戰起手邊界、windup 後命中邊界與略超出；弓用中心距邊界，不誤加半徑。控制測試使用整除與不整除分段時間的 dt，確認三秒總期限、跨段推進、死亡不復起、定身交互；不能只斷言三個常數相加。

## 收尾新增驗收

以候選 A 加 world.matchDuration=300 作建議落地值，待 main 暫定；dev 為雙表單一寫手。補驗 A300 已有 98 自然／2 裁定／0 平局，但裁決只在分析 runner，不能當成引擎實作測試。正式判勝需測：時限前一人、時限後一人、多人生存唯一最高比例、最高比例同分、全滅；不同比例但顯示百分比相同時不可誤判平局。以兩位 hp 整數交叉相乘，不能用絕對 hp 或陣列順序破同分。

另測在途箭、投送與持續傷害先清算後裁決、清算中禁止新介入、裁決不觸發擊殺獎勵或 fury，UI/log 明示結果理由。保留自然勝與跨時限清算後殲滅勝的時間資訊；300 秒是行動截止，實際終場可能略晚。design 後續核對74列表與metadata，原73列凍結實驗資料不回寫。

## 比較與體驗驗收

dev 依 spec 的三組固定 seed 合約回逐局資料及摘要，design 核對分母、平局與截尾戰長，不把無介入組推論成作弊樂趣。缺少裝備或控制情境就由定向測試補，不外推不存在的樣本。只跑現況不得標候選驗證完成。

qa 檢查桌面與手機資訊可讀；名單、詳情、支持者 HUD 與已有 log／傷害回饋的 hp 數字一致採最多兩位小數去尾零，覆蓋 9.72、9.7、10、0.01、0 及 99.99 / 100 寬度，aria-valuenow 與實際 hp 相同、血條仍依實值比例；體力顯示不誤改，象狼文案與效果、耗盡後移動／恢復、盾防與三段控制。既有捕獸夾及牌庫回歸照舊；需固定 seed 可重現。報告測試是否自動出牌、是否自然抽牌，不把定向 UI 測試稱真人趣味驗收。
