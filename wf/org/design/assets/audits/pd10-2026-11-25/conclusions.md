# PD10 分析結論

[分析計畫](README.md)｜[dev 永久證據](../../../../dev/assets/pd10-2026-11-25/README.md)｜[預設索引](../../pending-defaults.md)

## 判讀

直接法術難啟動，首先是這套政策的牌型限制，不是所有失敗都缺石。新版 3664 個執行窗口中，2852 個沒有政策牌、395 個總石不足、409 個指定色不足，成功 8 次；沒有合法目標、冷卻與其他主因均為零。無政策牌占 77.84% 是窗口占比，不是獨立對局比例；同一副阻塞手牌可能反覆被計數。

擴大到全牌後，新版有 94/100 局至少成功一次、1984 次出牌；舊版有 93/100 局、264 次出牌。直接政策則分別只有 8/100 與 7/100 局成功。這支持「只允許直接法術且不換石」大幅限制啟動，不能以原先的八次成功代表全部作弊機制。全牌不是最佳策略，成功也不等於有效傷害：包含資訊牌、增益、治療、裝備及可能幫到其他鬥士的動作。

不能由失敗總數推定 V3 經濟退化。舊直接僅有 279 個窗口，新版有 3664；兩版同 seed、同 scheduled 且都可介入的交集，直接各 279 窗口／7 次成功，全牌各 287／264。直接配對主因仍有小幅差異（新版總石不足 33／色不足 23，舊版 31／25），不能說每個窗口狀態完全相同。配對只觀察共同存活與可介入時段，也不能代表新版獨有的長期問題不存在。

## 收入節奏

兩版原生起手、牌庫、費用及補石規則沒有改變。每局起手三石；成功出牌補兩石，支持者擊殺補三石。這些是本次固定 revision 的實驗條件，不是新提案或另立的 runtime 權威。四組每組起手合計 300 石，逐色事件及末態皆可對帳。

新版支持者擊殺補石確實較晚。直接政策首次支持殺發生於 23 局，發生者中位時間 102.467 秒；舊版為 8 局、15.833 秒。全牌為新版 35 局、88.233 秒，舊版 19 局、15.200 秒。未發生局數分別為 77、92、65、81，不能把發生者中位數視為所有玩家的等待時間，也不是同一組事件的配對因果估計。

「擊殺變少，所以總補石變少」不符合本次全局資料：新／舊直接的支持殺補石合計為 81／60，新／舊全牌為 129／102。新版戰局與狼可介入時間更長，收入較晚但全局總量並未較少。成功出牌補石新／舊全牌為 3968／528，付款為 3426／421；這顯示成功出牌與補石、補牌形成循環，不能只研究擊殺收入而忽略出牌循環。版本整體比較仍無法單獨識別血量、傷害或其他戰鬥參數的因果效果。

## 全牌仍卡色

新版全牌的 1183 個失敗窗口全部是指定色不足，分布於 60 局；52 局最後一個可介入窗口仍卡色。六個零成功 seed 為 9、20、28、29、46、61，手牌首末不變；seed 9 雖有支持殺補石仍未啟動，其餘五局石庫存也未變。不能把 1183 當成獨立失敗樣本，或把 94 局成功至少一次解讀成整場體驗流暢。前四組全牌政策未用換石；以下 v1 追試補量既有解套操作的效果。

## 後續選項，不調新數值

前四組建議先測既有換石策略、不先加資源；main 隨後授權單組追試，結果見下節。既有簡單政策已使這批六局零啟動全部啟動，目前不建議由本批直接推導新經濟數值；下一步宜由策劃／真人回看換石操作負擔、持續可操作性及介入效益，再決定是否擴充政策或樣本。這是建議，不是平衡接受或替使用者決定改版。

若既有操作仍無法解套，再由策劃選擇檢視起手可支付性、色石取得／轉換，或牌循環限制。選項分別對應起手零啟動、總數夠但卡色、直接政策無適用牌；本次不提供新的石數、機率或補牌數，也不保證提高總石數能解決色別不足。

若策劃希望作弊收入更少依賴戰鬥擊殺，可另檢視收入來源與時點；依據是新版首次支持殺明顯延後，而非總收入減少。須先決定要改善「首次啟動」、「持續可操作」還是「介入效益」，三者不是同一目標；不由本報告替使用者選擇改版。

## 換石 v1 追試

[政策契約](redraw-policy-v1.md)｜[dev 追試證據](../../../../dev/assets/pd10-redraw-v1-2026-11-25/README.md)

只新增 V3 同 revision、seed 1..100 的一組，基準沿用前次新版全牌，不重跑、不改數值。每窗先正常出牌；連續兩個已執行窗口主因卡色，才以原生 API 棄第一張手牌、換第一顆庫存石，不選色或優化。換石成功後不在同窗再出牌；卡色仍按換前分類，換石不算正常出牌成功。

基準至 v1，正常出牌由 1984 增為 2959，至少一次正常出牌由 94 增為 100 局，零正常出牌及零有效動作都由 6 降為 0。全局窗口 3167 至 3135，換前卡色 1183（37.35%）至 176（5.61%）。同 seed、同 scheduled、兩政策均可介入的 2990 個窗口，正常出牌為 1960 至 2814，卡色為 1030（34.45%）至 176（5.89%）；配對仍有存活選擇及策略改變戰鬥／RNG 的限制。

末窗卡色由 52 局降為 4 局，剩 seed 42、90、98、99；seed 90 末窗換石成功但沒有下一窗口，不稱已解套或永久死鎖。dev 逐局摘要顯示原六零啟動 seed 9、20、28、29、46、61 本輪正常出牌依序 29、20、13、30、24、14 次，首次皆約 15 秒。86 次換石嘗試全部成功；dev 統計其中 85 次其後觀察到正常出牌，等待中位 5 秒、平均 5.824 秒、最大 15 秒，另一次未發生。不同換石可能共用後續同一次出牌，並非 85 個獨立局或單次換石的因果效果。

平均戰長 228.901 至 225.125 秒、中位 221.967 至 216.167 秒；平均狼可介入時長上限 160.910 至 159.451 秒。出牌增加不能單獨證明有效傷害提高。本輪收入為起手 300 石、正常出牌 5918 石、換石 172 石、支持殺 180 石；支出為正常出牌 5154 石、換石 86 石，末態共 1330 石。這些是固定實驗的對帳數，不是新預設。

本次支持「既有簡單換石在固定樣本減少卡色，讓六個原零啟動局啟動」，不支持最佳策略、真人操作負擔低、趣味或平衡已接受。換石同時改手牌、色石與 RNG 消耗，不能將效果只歸因補石量。

## 核對與驗證界線

design 以 tabledb 讀四組原始各 100 seed，獨立重算窗口主因、成功局數、配對窗口、逐色每事件與末態庫存，以及六局未成功／六十局卡色／五十二局末窗卡色；均與 dev 摘要一致。核對當時 manifest 列出的檔案大小與 SHA256 全數相符。之後依 main 要求，六份 raw 原始資料移至 `/tmp/aos/arena_cheater/dev/pd10-2026-11-25-raw/`；dev 回報搬移前後 SHA256 不變，manifest 已標示 externalPath／inRepo。此路徑是暫存，不是永久備份；repo 保留摘要、配對、卡色明細、runner 與驗證紀錄，不再包含逐窗口 raw。本報告不另建原始資料副本。

dev 四組最終受控 test/build 通過且 scope 清理完成；這是隔離量測 runner，不是重跑正式完整核心測試或 UI 驗收。收入來源最初的鄰接推斷曾觸發量測斷言，修正為原生呼叫點標記後統一重跑，兩直接組除來源欄外資料不變。design 查核腳本初次將事件誤稱 payment、及向 tabledb 傳入 Path 而非字串曾報錯，均依實際資料／API 修正後通過，非產品問題。沒有重跑 Node、沒有改正式數值。

前四組不測換石；追加 v1 僅測上述單一政策，仍不測真人趣味、最佳玩法或全牌延遲傷害的精準歸因；以上結論限於固定支持狼、指定窗口節奏與兩個固定 revision。PD10 保留為待遊戲策劃回看，不因分析完成就宣告平衡已接受。


追試由 design 另以 Python／tabledb 核對 100 seed 初始化與基準一致、連續卡色門檻、首牌首石、重設計數、正常出牌與付款事件數、每事件逐色及終局守恆、全局主因／零成功／末窗卡色、共同窗口與戰長；全部通過。manifest 內 repo 證據及外部 raw 的大小與 SHA256 皆相符。原六 seed 詳細出牌數及換石後等待分布採 dev 摘要，未宣稱 design 另作獨立重算。

追試 raw 在 `/tmp/aos/arena_cheater/dev/pd10-redraw-v1-2026-11-25/new/`，基準 raw 沿用前述外部暫存；都不是永久備份。永久保留的摘要、逐局比較、政策核對、runner／插樁及 manifest 見 dev 追試證據。兩次 arena_verify 等鎖逾時、steps 為空，第三次 test/build 通過且 scope_cleaned=true；stop_exit_code=5 對應 scope inactive/not-found。這仍是隔離 runner 驗證，不是正式全套核心測試或 E2E；design 沒有跑 Node。
