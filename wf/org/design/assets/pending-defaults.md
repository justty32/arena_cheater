# 可調預設索引

[資產庫](README.md)｜[改進記錄](../improvements.md)

讓 main 彙整規格仍未確認的預設時，不必重新閱讀全部 spec。資料在 [pending-defaults.json](data/pending-defaults.json)，由 design 維護。這是規則與裁示的索引，不是進度板、WAIT_USER 或數值設定檔；數值仍以程式為準，方案理由回到原 spec。

## 收錄邊界

第一批只整理兩次規劃已接觸的 V2 資源循環與捕獸夾授權，不宣稱涵蓋所有舊版預設。未收錄不代表已確認；「未確認」指所引證據沒有明確確認，不代表使用者一定從未在別處同意。main 若有其他裁示應補入依據，不用重新詢問。

捕獸夾已授權，不能再列成需要使用者拍板。此次同意只限捕獸夾提案，不擴大解讀為同意整套 V2 數值、種子或 V3 遷移。V3 狼／象固定加值是來源要求變更，不是現行倍率的可調預設；應走遷移規劃而非要求使用者再次確認原文。

## 欄位與維護

`id` 為穩定索引，`topic` 是決策主題，`requirement_ids` 連回需求。`confirmation` 分為未確認或已同意；`blocking` 說明是否真正在阻擋已選切片，不以未確認自動推定阻擋。

`question` 給 main 彙整問題，`recommendation` 是策劃建議而非裁示。`source_path` 指向完整規格，`evidence` 記授權原話或尚缺的依據，`scope` 標明這筆涵蓋範圍。

每次交付新 spec 時，只為原文未定且仍採用的預設新增或更新相關主題。收到授權先核對適用範圍，再改 confirmation 與 evidence；實作完成不會自動變成已同意。可調預設若被新來源取代，應改記取代依據並交接遷移，不沿用過時問題。真正需要使用者解除的阻礙仍寄 NEEDS-USER 給 main，由 main 維護 WAIT_USER；不在此存當前負責人或工作進度。
